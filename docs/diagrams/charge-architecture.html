运行架构：旧入口接入新 C 模块

主路径从左向右；设备副作用经平台回到原驱动。两个平台方框表示同一适配层的不同职责。

日常开发落在可移植模块

firmware/include/charge/ 定义公开契约。领域层处理规则，协议层处理字节，存储服务通过回调表达副作用。时序、分配和原 ABI 的兼容责任留在平台及调用者。

迁移边界保持可见

原启动、调度器、复杂业务、IRQ/DMA、多数驱动与 Boot 仍由汇编承担。RX 新 API 要求独立的 256 字节缓冲，其分配及回调时序尚未完成原生集成。

构建架构：开发固件与恢复证据分开

原始 HEX 只作为只读基准。开发镜像通过生成的兼容汇编与新 C 链接；恢复工程保留独立构建路线。

左右滑动图面，可查看完整架构。

布局约束

Boot 0x08000000–0x08003FFF；App 0x08004000–0x0800F7FF，其中末尾 10 KiB 留给 C 扩展；metadata 0x0800F800–0x0800FBFF；config 0x0800FC00–0x0800FFFF。

验证结论各有范围

主机测试、原始 Thumb 差分、原生入口与调用链检查用于开发验证。恢复工程的字节一致记录独立存在。上述检查均不能代替真实设备上的时序、并发、栈与升级验收。
