# 应用程序静态分析

证据来源：`artifacts/firmware.bin`（原 HEX 的完整 64 KiB 解码），以及 GNU ARM objdump Thumb 反汇编 `artifacts/firmware.linear.thumb.asm`。本笔记没有运行板上程序；线性反汇编中的常量池、跳转表并不都是指令。

## 已直接确认的结构

- 应用向量表在 `0x08004000`；`0x0800A708` 是应用主入口。
- `0x0800A710–A71E` 复制 **45 个向量** 到 `0x20000000`；`A720–A740` 打开 SYSCFG 时钟并设置低两位 `MEM_MODE=3`，把 SRAM 映射到零地址。
- `0x200005E4` 有 **12 个 52 字节对象**，循环边界在 `0x08009DF0`、`0x0800AF34`；可见倒计时、测量量、状态、多个标志。`application.c` 保留了精确偏移，字段名是分析者命名。
- `0x200008D4` 是 **93 个 uint16_t 软件计时槽**；清零循环 `0x08009D94–9D9E`，主循环遍历 `0x0800A7FA–AC62`。若新时间值小于上次值，`A7E4` 强制本次差值为 1；并非正常模 65536 求差。
- `0x0800C85C` 更新 `0x200000B8` 的通道位图以及 `0x200000DD` 起 3 个字节的双位状态码。12 通道分别占 1 位/2 位，状态码 01 与 10 对应调用参数零/非零。此函数本身只更新 RAM；主循环 `0x0800B0A6` 调用 `0x08007474` 把位图送到外部移位寄存器，完整链条见下。
- `0x0800B01A–B054` 在主循环中消费两组串口接收标志/长度，并分别执行整帧校验和逐字节解析。

## 外设初始化

地址名称使用 ST 官方 [STM32F0 CMSIS 头文件](https://github.com/STMicroelectronics/cmsis-device-f0/blob/master/Include/stm32f030x8.h) 和 [RM0360](https://www.st.com/resource/en/reference_manual/dm00091010.pdf) 的地址映射。外设地址匹配 STM32F0 兼容布局。主 agent 已查看用户补充的 `主板.png`，MCU 丝印明确为 Geehy APM32F030C8T6，故实物型号应使用 APM32F030C8T6，而非把 HEX 文件名中的 STM32 当作实物型号。寄存器名仍按兼容布局解释；外接芯片功能需要电路确认。

| 函数地址 | 观察结果 | 证据 |
|---|---|---|
| `0x08007DE8` | GPIO 初始化，涉及 GPIOA/B/C/F 时钟 | RCC AHBENR 位 17、18、19、22；端口基址 0x48000000/400/800 |
| `0x08007DB0` | DMA 时钟及 IRQ 10/11 设置 | RCC AHBENR 位0，NVIC 参数10/11 |
| `0x08007D44` | ADC1，配置通道9 | 基址 0x40012400；`7D86` 参数9，sample-time 参数5 |
| `0x08007FC4` | TIM1，预分频47、周期999 | 基址0x40012C00；参数在7FDC、8030 |
| `0x08008034` | USART1，9600 baud，收发模式 | 基址0x40013800；75<<7 = 9600，mode12 |
| `0x0800806C` | USART2，同为9600 baud | 基址0x40004400，同组参数 |
| `0x08007F38` | I2C1，timing值0x10D55F7C | 基址0x40005400，寄存器式初始化结构 |
| `0x08007F90` | IWDG，参数 prescaler5、reload0xC35、window0xFFF | 基址0x40003000 |

`0x0800A780–A794` 为两路串口分别传入512字节接收缓冲区：`0x20000C10` 与 `0x20000E14`。调用 `0x08006DCA`，与 UART DMA 接收入口一致。是否为 DMA 已结合函数行为推断；精确 HAL 版本没有识别。

## 两种校验/解析路径

1. `0x08008E84`：对 `frame[1..length-2]` 做 XOR，与末字节比较，成功后调用 `0x0800B0DC`。注意其 XOR **排除头字节0**。
2. `0x08008EAC`：状态机位于 `0x20000124`，缓冲区 `0x20001024`，接收 `0x55`、`0x44`、`0xAA` 头字节。
   - `0x55 0xAA ...` 为固定9字节路径，前8字节全 XOR 等于第9字节，调用 `0x08009694`。
   - `0x44 0xAA ...` 为固定27字节路径，全帧 XOR 为零才把 `buffer+3` 交给 `0x0800C830`。
   - 首字节0x55/0xAA且次字节不是0xAA时，以次字节+2作为总长并切换/保持 mode1。**观察到的这个接收函数在 mode1 完成后直接清零状态，没有调用分发器**；不能自行补成“已完整还原的协议”。
   - 完整命令分发器 `0x0800B0DC` 读取 `frame[2]` 为命令，`frame[4]` 起为参数；可见0x10、0x2C、0x2D、0x36等命令路径，业务名称暂未完整还原。

`application.c` 给出两条校验/解析路径的逐指令人工整理，保留了 mode1 的原有行为。

## 移位输出、存储与显示

- `0x08007474` 从通道位图 `0x200000B8` 读取16位，先高字节后低字节调用 `0x08007400`，每字节高位先发；PB8为时钟、PB3为数据；`0x08007450` 把PB5先拉低后拉高锁存。与照片中U8/U9的74HC595D对应度很高。可以确认固件有16位串行移位输出，其中低12位用于通道；没有追线前不确定每一位连接到哪个端子或继电器。
- `0x08007498`/`0x080074FC` 是I2C地址参数0xA0、16位存储地址、128字节写页边界、65536字节地址空间的存储读写；`0x080074C4` 实施写后就绪轮询。推测是24C512类64KiB EEPROM，但未从照片确认具体料号。

## 显示与外部命令输出

- `0x0800882C` 经 PB15 时钟、PA8 数据发送字节，**低位先发**，8位；上层使用0x40、0xC0/0xC6、0x8A控制字，显示数据写入为6字节。与数码管驱动类协议相符，但具体 TM16xx 型号未经电路确认。
- `0x0800CDB8` 在 PB10 上发8位脉宽编码，低位先发，1位采用720/240延时参数，0位采用240/720。先有5单位前导、后有1单位收尾，分别调用另一延时例程。支持命令0..0x49及0xE0..0xE7。很像外接语音模块控制，但型号/音频内容/延时物理单位未知。
- 通道倒计时以60作除数（`0x08009E40`），具有多档阈值、状态显示和完成/停止后的上报行为。结合12通道结构、照片刷卡模块接口和74HC595，**推测为支持刷卡的多路计时/计量控制设备**。仍不能直接给字段补上“瓦/安/分”等单位。

## 人工恢复的范围和限制

`reconstructed/application.c` 包含通道结构、软件计时差值/扣减、整帧XOR校验、逐字节解析、通道状态打包、部分通道清零、移位寄存器输出、两类GPIO位发送例程。函数名和变量名不是从二进制找回的原名。

完整应用主循环还包含93项计时器的跳转表分发、12路阈值和状态机、1..15号输入轮询/消抖、配置与通信处理；本文件没有假装已经把这些都实现。它通过 `arm-none-eabi-gcc -std=c11 -mcpu=cortex-m0 -mthumb -ffreestanding -fsyntax-only -Wall -Wextra` 语法检查，但外部 `fw_*` 仍待还原，不能整体链接或刷机。四个局部函数已做下面的离线机器码差分验证；其余部分没有运行等价性验证。

## 离线机器码差分验证

执行 `python3 recovery/tools/verify_semantics.py`。脚本把本文件的四个目标函数用 ARM GCC -O2 编译，然后在两个 Unicorn Thumb/MCLASS 实例分别运行原固件机器码和新编译的C机器码，比较低12KiB SRAM全部字节、GPIO/延时调用顺序与参数。没有连接或执行实体硬件。

| 目标 | 测试 | 结果 |
|---|---|---|
| 0x0800C85C 通道状态 | channel0..255 × enabled0/1/2/255 ×3套随机RAM，含255加1回绕后的默认无操作 | 3072例通过 |
| 0x08009E14 清理 | 12通道 ×20套随机RAM | 240例通过 |
| 0x0800CDB8 脉宽命令 | 命令0..511 ×状态标记0/1/2 | 1536例通过 |
| 0x0800CDA4 配置命令 | 配置0..255 ×状态标记0/1 | 512例通过 |

总计 **5360例通过、0失败**，报告 `artifacts/verification_semantics.json` 保存原固件/C文件/编译产物SHA256、版本、种子和测试范围。验证时发现并修正了脉宽命令参数的宽度：必须保留32位，否则配置字节加0xE0后会发生错误的8位回绕。

这是有限范围的差分仿真，**不是全固件等价证明**；外设被截获为调用事件，真实电气效果、时间、并发中断未验证。协议解析器、显示和完整主循环未列入本次差分测试。

## 额外恢复的存储读写

`application.c` 还人工翻译了 `0x08007498` 读函数、`0x080074C4` 就绪轮询、`0x080074FC` 页写函数，保留128字节页拆分、16位地址和写后轮询行为。它们通过语法检查，但**未纳入上述差分仿真**。底层I2C仍为明确标记的外部函数，不能据此声称已还原完整驱动库。
