# 完整应用 main 的显式 C 控制流参考

`reconstructed/application_main.c` 与 `.h` 覆盖应用入口 `0x0800A708` 到循环尾 `0x0800B0C6` 的 **1053 条静态可达 Thumb 指令**。它保留地址标签、寄存器状态、APSR 标志、栈局部变量和固定 RAM 访问，用 C 运算表示每条指令；没有裸 opcode 解释器，也没有未实现的 main 分支。源码由 `tools/lift_application_main.py` 从 Capstone 操作数和已核对的 Keil switch8 规则生成。

这是机器状态层的完整 main 参考，不是原始高层 C，也不是可以直接放到 MCU 上链接的应用程序。`AppMainState.call` 是明确的外部函数边界：调用方必须实现真实被调函数的寄存器、标志、内存和外设效果；没有默默返回成功的驱动空实现。它与 `decompiled/functions/` 的 Ghidra 伪代码互为参考，尤其避免把常量池、跳转表或相邻函数误并入 main。

## 处理阶段

| 地址 | 行为 |
|---|---|
| A708–A740 | 复制45项向量，开启SYSCFG并重映射SRAM |
| A742–A7D2 | HAL/时钟/GPIO/DMA/TIM/UART/I2C/IWDG/ADC及业务初始化 |
| A7D4–A7F6 | 喂看门狗、读取时基并计算16位差值；回绕时差值固定为1 |
| A7FA–AC62 | 93项软件计时器扫描、非到期动作和到期分派 |
| AC64–ACB6 | 全局模式处理及周期事件 |
| ACB8–AF38 | 12个52字节通道对象的计量、阈值、状态和倒计时处理 |
| AF3A–B018 | 输入1..15轮询、短按/长按等待及消抖 |
| B01A–B054 | 两路串口数据消费 |
| B056–B0A4 | PB10命令队列消费 |
| B0A6–B0C6 | 移位输出、显示、状态采样与循环回跳 |

原循环末尾使用 BL A7D4，而不是 B；译文保留 LR 更新。main 没有返回路径。

## 93项计时槽与 switch 表

内联表在 A88E：第一个字节是 **81**，所以专用索引为0..80，所有≥81的索引使用默认分支。main仍扫描93项；不能将“93项计时槽”误称成“93个独立 switch case”。

| 到期槽索引 | 目的地址 |
|---|---|
| 0 | A8E2 |
| 1 | A914 |
| 2 | A966 |
| 3 | A96C |
| 4 | A9DA |
| 5 | A982 |
| 6 | A912，默认后续 |
| 7 | A9F2 |
| 8 | AA1E |
| 9..20 | AA2E |
| 21..32 | AA4A |
| 33..44 | AA74 → AC2A |
| 45..56 | A912，默认后续 |
| 57..68 | AA72 → AC4E |
| 69..80 | AA70 → AC34 |
| 81..92 | A912，默认后续 |

`artifacts/application_main_coverage.json` 列出全部指令、外部调用地址和 switch 目标。A88E..A8E1 是跳转表，AB04..AB57、AFC8..AFDB、B0C8..B0DB 是常量池，均不冒充指令。

## 差分验证

运行 `python3 recovery/verification/check_application_main.py`。在相同模拟 RAM、寄存器、APSR、外部调用约定下，Unicorn 运行原始 Thumb，系统 C 编译器运行恢复的显式 C。

347个场景全部通过，包括初始化、93个计时槽分别到期/未到期，以及160组确定种子的通道/全局配置。比较全64 KiB模拟SRAM、寄存器0..14、APSR NZCV、模拟MMIO写入、**23873个外部调用事件**（参数寄存器、LR、APSR与8个栈参数字）。动态执行覆盖695/1053条main指令，约66.0%。结果见 `verification/application_main_result.json`。

外部函数使用同一组显式模拟回调，未执行真实驱动或业务被调函数。按键默认不按下，未验证长按等待、硬件时序、中断、DMA和并发。静态控制流全部表达不等于所有业务条件都已动态验证；剩余未覆盖指令地址保留在JSON中，不能宣称全程序行为等价。
