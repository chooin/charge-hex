# 完整 C 语义模型独立审阅

审阅范围：`generate.py`、生成的 `firmware_model.h/c` 中的 CPU 状态、NZCV、移位、栈/多寄存器访问和控制流。此审阅不修改生成器，修复由模型实现者完成后再核对。最终审阅模型 SHA-256：

`fd9eae59017e724cd8b744ce346f7e3136bc556a3816733b8438867480c6470d`

在声明的单线程、Thread/MSP、已分类指令和显式总线接口范围内，没有发现尚未处理的阻断性语义问题。这里的“模型”仍不是完整 MCU 模拟器，也不是可烧录 C 工程。

## 已发现并修复的边界

1. **内存对齐。** 最初的内存帮助函数允许任意半字/字地址。Cortex-M0+ 的半字访问需2字节对齐，字/多字访问需4字节对齐，违规应进入 HardFault；这是 ARM 官方 [DUI0662A §3.3.4，印刷页3-8/PDF第44页](https://documentation-service.arm.com/static/5f04aadfdbdee951c1cdc957?token=) 的规则。当前模型在非对齐访问时显式返回 `-5`，不假装完成访问，也不假装实现了异常入口。
2. **首次故障保留。** 当前 `read_mem/write_mem` 在已有 fault 时立即短路；`fault()` 不覆盖已存在的错误。避免多寄存器指令在第一次失败后继续触发总线访问，或把首次错误地址覆盖成后面的地址。
3. **故障PC诊断。** 当前 `STEP` 在更新 PC 之前检查已有 fault，因此内存失败后不会把诊断 PC 误移到下一条指令。后续寄存器/栈回写状态不宣称复刻真实异常精确状态，文档已明确此限制。

本机 Unicorn 2.1.4 在 MCLASS 模式仍容许部分非对齐访问，不能把“与 Unicorn 一致”当作这一架构规则的依据。正常指令对照限制为有效对齐地址，错误边界使用独立的模型断言。

## 重点静态核对

| 领域 | 结论与范围 |
|---|---|
| ADD/ADC/SUB/SBC | 使用64位无符号中间量求进位；减法进位按无借位处理；溢出按输入/结果符号关系计算。NZCV更新互不覆盖。 |
| LSL/LSR/ASR | 零移位保留C；寄存器移位取低8位；32与大于32分支避免C语言未定义移位。ASR大位移按符号填充。 |
| 逻辑/MUL/MOVS | 更新N/Z并保留C/V；不置标志的MOV/ADD/SUB不误更新APSR。 |
| 条件跳转 | 有符号条件使用N/V关系，无符号条件使用C/Z；布尔表达式的C优先级符合意图。 |
| PUSH/POP | 使用原SP保存访问地址，按寄存器号顺序访问，再更新SP。POP PC交给Thumb目标检查，不将返回值当普通数据继续执行。 |
| LDM/STM | 保存基址后逐寄存器访问，使用Capstone的writeback信息；基址本身在LDM列表中时保留加载值，不误覆盖。该规则与同一ARM指南§3.4.5（印刷3-16/3-17）一致。 |
| BL/BLX/BX | BL保存下一条地址加Thumb位；BLX先缓存目标再改LR，避免目标寄存器为LR时读到新LR；动态目标落入模型自身已翻译代码。 |
| MSP | 模型只表示当前MSP，不实现PSP/CONTROL切换；MSR MSP清低两位。测试正常路径使用对齐SP，不能以Unicorn对未对齐SP的行为裁定实物芯片规则。 |
| PC相对读取/ADR | literal和ADR使用对齐的PC+4基址；普通寄存器读取PC按该指令PC+4处理。 |
| 异常返回/外设 | 明确拒绝未提供的异常返回和总线行为。没有用成功空函数代替这些语义。 |

## 独立边界对照结果

新增 [review_boundaries.py](review_boundaries.py) 从当前源码在独立临时目录编译动态库，与原始 Thumb 指令比较，不复用 `libfirmware.dylib`，不导入会执行其他测试的脚本。它记录全部输入源码 hash，运行结束再次确认源码未被并发修改。

| 原始地址 | 指令组 | 样本数 |
|---|---|---:|
| `080000FC` | LSL寄存器移位 | 1008 |
| `080000F4` | LSR寄存器移位 | 1008 |
| `08000158` | ADC | 784 |
| `08000136` | SBC | 784 |

**3584例全部通过。** 包括所有16种初始NZCV组合，移位值0、1、31、32、33、255、256、257、FFFFFFFF，以及0、1、7FFFFFFF、80000000、FFFFFFFE、FFFFFFFF等运算边界。比较r0..r14、PC、NZCV。

```sh
python3 recovery/full_c/review_boundaries.py
```

完整结果和最终源hash绑定见 [review_boundaries.json](review_boundaries.json)。这是主测试 `verify.py` 之外的补充；不把这3584例外推为所有状态的形式化证明。精确异常现场、IRQ并发、外设/DMA、Flash控制器和硬件时序仍未验证。
